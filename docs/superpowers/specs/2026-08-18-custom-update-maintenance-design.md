# FlairX 自定义功能长期维护设计

日期：2026-08-18

## 目标

让本地增加的 GameBanana 角色筛选、Liked/Downloads 排序和高清缩略图功能在 FlairX 官方升级后仍可继续使用，并将源码安全保存到用户的 GitHub Fork。

## 范围

本次工作包括：

- 创建 `Dyendless/FlairX-Mod-Manager` Fork。
- 保留 `origin` 指向官方仓库，新增 `fork` 指向用户 Fork。
- 建立长期分支 `custom/gamebanana-enhancements`。
- 提供一个 PowerShell 一键维护脚本。
- 提供中文操作说明。
- 在更新过程中执行测试、构建、备份、部署和失败恢复。

本次不自动创建官方 Pull Request，也不建立独立更新服务器或自定义 Release 渠道。

## 仓库与分支模型

- `origin`：`Jank8/FlairX-Mod-Manager`，作为官方上游，只拉取不推送。
- `fork`：`Dyendless/FlairX-Mod-Manager`，保存用户的长期维护分支。
- `custom/gamebanana-enhancements`：长期维护分支，包含官方源码及用户定制提交。

首次设置时，从当前已验证的定制版本创建长期分支并推送到 `fork`。以后更新时，脚本读取官方最新稳定 Release 对应的标签，将它合并到长期分支。采用合并而不是反复变基，以避免强制推送并保留清晰的升级历史。

## 一键维护脚本

脚本放在仓库的 `tools` 目录，默认安装位置为 `E:\flairx`，并允许通过参数指定其他位置。

执行流程：

1. 验证当前仓库、长期分支、Git、GitHub CLI、.NET SDK 和安装目录。
2. 拒绝在工作区存在未提交修改时继续。
3. 从官方仓库获取标签，并查询最新稳定 Release。
4. 如果长期分支尚未包含该 Release，则尝试合并。
5. 如果发生冲突，自动中止本次合并并退出，不修改安装目录。
6. 运行完整测试和 Release 构建。
7. 下载官方 Release ZIP 到独立临时目录并解压。
8. 将当前源码构建出的自定义应用产物覆盖到暂存发布包的 `app` 目录。
9. 验证暂存发布包包含启动器和主程序。
10. 在 `E:\flairx\backups` 下创建带时间戳的完整安装备份。
11. 停止 FlairX 主程序和启动器，将暂存发布包部署到安装目录。
12. 验证关键文件存在并启动 FlairX。
13. 若部署或启动验证失败，恢复更新前备份。
14. 成功后将长期分支推送到用户 Fork。

脚本应支持 `-WhatIf` 或等价的预演模式。预演只完成检查并打印将采取的操作，不下载、合并、构建、终止进程、备份、部署或推送。

## 安全边界

- 安装路径必须解析为明确的绝对路径，且必须包含现有的 `app\FlairX Mod Manager.exe`，否则拒绝执行。
- 删除和覆盖只允许发生在本次创建的临时目录、明确的安装目录以及该安装目录下的 `backups` 目录。
- 在测试和构建全部成功之前不停止应用、不创建部署备份，也不覆盖安装文件。
- 合并冲突时恢复到合并前的干净 Git 状态。
- GitHub 推送只针对 `fork/custom/gamebanana-enhancements`，不向 `origin` 推送。
- 日志与错误输出不得显示 GitHub 访问令牌。

## 备份与恢复

每次实际部署前，将当前安装内容复制到：

`E:\flairx\backups\yyyyMMdd-HHmmss-custom-update`

为防止备份递归复制，备份内容排除安装目录自身的 `backups` 文件夹。部署失败时，用该备份恢复安装根目录的程序文件。历史备份默认保留，不自动删除。

## 测试策略

脚本中的纯逻辑部分拆分为可测试函数，至少覆盖：

- 安装路径保护。
- 最新 Release 标签选择或解析。
- 合并冲突不会进入部署阶段。
- 测试或构建失败不会进入部署阶段。
- 备份目录不会递归包含 `backups`。
- 推送目标只能是 `fork` 的长期分支。
- 预演模式不会产生外部修改。

实现阶段遵循测试先行。除自动化测试外，还将执行：

- 项目完整测试。
- x64 Release 构建或发布。
- 脚本预演。
- 在 `E:\flairx` 上进行一次真实备份、部署和启动检查。
- 检查 GitHub Fork 与远端长期分支是否存在。

## 使用方式

日常更新只需在仓库中运行维护脚本。正常情况下脚本自动完成官方版本同步、验证和安装；遇到源码冲突时停止并提示用户寻求人工合并，现有 FlairX 安装保持不变。

## 验收标准

- GitHub Fork 和远端长期分支存在，包含当前定制提交。
- 一键脚本在干净工作区能够安全执行预演。
- 任一前置验证、合并、测试或构建失败均不会覆盖安装目录。
- 实际部署前产生可恢复的完整备份。
- 成功部署后 FlairX 可启动，GameBanana 角色筛选、排序和高清缩略图仍可使用。
- 中文说明明确记录首次配置、日常更新、冲突处理和手动回滚步骤。
